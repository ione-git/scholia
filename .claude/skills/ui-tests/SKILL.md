# UI tests

Every screen has two kinds of test, both XCUITest, both in the screen's own test class:

- **Flow test** — a user scenario. Launch, act through screen objects (tap, type, swipe), assert the outcome through accessibility queries: a screen opened or closed, a book appears in or leaves the library, a value changed or survived a relaunch. No images.
- **Snapshot test** — how a screen looks. Drive the app to one state, capture the app window and compare it with a reference image committed under `UITests/__Snapshots__/`. One test per appearance: light and dark (iPad later).

## Which one

| You want to prove | Test |
|---|---|
| Tapping X opens Y; Back or Cancel returns | flow |
| An item appears, disappears, reorders, is filtered | flow |
| A choice is selected, a value changed, it persists after relaunch | flow |
| Data reached storage, the translation mock, the notification centre (`debug.*`) | flow |
| An icon-only control has its VoiceOver label | flow |
| Spacing, sizes, alignment, colours, fonts, radii, glass, which text is shown and how | snapshot |
| Light and dark look | snapshot, one test per appearance |

A flow never checks layout and a snapshot test never checks behaviour.

## Where things live

- `UITests/<Screen>Tests.swift` — flow and snapshot tests of one screen area, subclass `UITestCase`.
- `UITests/Screens/<Name>Screen.swift` — one screen object per screen, sheet, popover or alert.
- `UITests/__Snapshots__/<TestClass>/<Name>.light.png`, `<Name>.dark.png` — reference images, committed. Excluded from the test target's sources in `project.yml`.
- `UITests/Support/` — `UITestCase` (launch, stops at the first failure), `Snapshot.swift` (`assertSnapshot`), `Screen` protocol, waits.
- `App/Sources/LaunchConfiguration.swift` — `LaunchConfiguration`, `Fixture` and `TestAnimations`, compiled into the app and the tests.
- `Fixtures/*.epub` — generated by `python3 scripts/make_fixtures.py`; commit the outputs. Bundled into the app as `Fixtures/` in Debug only; Release excludes them (`EXCLUDED_SOURCE_FILE_NAMES` in `project.yml`). Also bundled into the test target: `try fixture.file` is its URL there.
- Import a file the way another app's "Open in…" does: `app.open(try fixture.file)` (see `HomeScreen.openFromOtherApp`). The system Files picker cannot be seeded, so tests only check that it appears (`FilePickerScreen`).
- Snapshot library: [pointfreeco/swift-snapshot-testing](https://github.com/pointfreeco/swift-snapshot-testing), pinned exactly in `project.yml`, linked only into `ScholiaUITests`. Tests never import it; they call `assertSnapshot(of:named:)`.

## Accessibility identifiers

`screen.element`, both parts lowerCamelCase: `home.wordmark`, `library.searchField`, `reader.pageCounter`, `addBook.title`.

- Sheets, popovers and alerts are screens of their own.
- Repeated items: `screen.element.<key>`, key stable and known to the test (book title), never an index or UUID: `library.book.Die Verwandlung`.
- `debug.*` is reserved for Debug-only diagnostics.
- Find elements by identifier, check text through `.label`.
- Exception: SwiftUI `.alert` drops identifiers. The alert is `app.alerts.firstMatch` (its label is the title), buttons are `alert.buttons`; see `ImportFailureAlert`.

## Launch configuration

```swift
let app = launch(LaunchConfiguration(resetsState: true, fixtures: [.german], opened: [], inProgress: [], highlighted: [], translation: .immediate, now: nil, notificationPermission: nil))
let dark = launch(configuration, appearance: .dark)
```

| Field | Environment key | Meaning for the app |
|---|---|---|
| `resetsState` | `SCHOLIA_RESET_STATE=1` | start with empty storage and settings |
| `fixtures` | `SCHOLIA_FIXTURES=german,drm` | library holds these books, added if missing: title, author, language from the table below, no cover yet, file copied into the app container |
| `opened` | `SCHOLIA_OPENED=drm,german` | these stored books were opened, most recent first: the first at `now`, each next one a minute earlier |
| `inProgress` | `SCHOLIA_IN_PROGRESS=german` | these stored books have a saved reading position (chapter 1, offset 0), so Book Info shows "In progress" |
| `highlighted` | `SCHOLIA_HIGHLIGHTED=german` | these stored books have 7 highlights, added if the book has none |
| `translation` | `SCHOLIA_TRANSLATION=mock` or `held` | translation provider is the mock: `.immediate` answers at once; `.held` records the request, then waits until it is cancelled, so the loading state stays on screen |
| `now` | `SCHOLIA_NOW=<ISO 8601>` | the app's current date and time |
| `notificationPermission` | `SCHOLIA_NOTIFICATIONS=declined` or `denied` | turning the reminder on gets this answer without asking the system: `declined` as if "Don't Allow" was tapped on the prompt, `denied` as if notifications were already off |

- The app reads `LaunchConfiguration.current` where it builds a dependency (storage, translation provider, clock). A missing key means off, so a plain launch is a normal launch. Parsing exists only in Debug; Release always gets everything off.
- `resetsState: true` unless the test checks persistence across a relaunch. Fixtures get `now` as their added date; for different added dates seed some books, `terminate()`, and relaunch with `resetsState: false`, the other fixtures and a later `now` (`LibraryTests/testEachSortOrder`). `translation: .immediate` unless the test needs the loading state (`.held`). Set `now` whenever the screen shows dates, reading time or the daily goal.
- Rendering is the same on every Mac and on CI:
  - `scripts/sim create` pins the simulator: iPhone 17 Pro (iPad Pro 11-inch (M5) with `--ipad`), iOS 26.4 runtime, language English, region `en_US`, text size Large, light appearance. It applies them on every call, so run it before a session; a simulator not prepared by it gets other formats and fails snapshots. Runner and app share the region, so expected strings the test formats itself (`formatted(…)`) match the app.
  - `launch` sets `TZ` to GMT (another zone: `launch(configuration, timeZone: …)`); the app needs nothing, `TimeZone.current` and `Calendar.current` follow `TZ`.
  - `launch` turns animations off: `SCHOLIA_ANIMATIONS=off` (`TestAnimations`) makes the app call `UIView.setAnimationsEnabled(false)` and strip SwiftUI animations at the root (`transaction.animation = nil`, `disablesAnimations = true`). Debug only.
- `launch(_:appearance:)` sets the simulator to light or dark before launching and restores it after the test. Use it for every snapshot test and for flows about the theme.
- New switch: add a field and key to `LaunchConfiguration` (`init(environment:)` and `environment`), then honour it where the dependency is created.
- `debug.launchConfiguration` (any screen: `screen.launchConfiguration`) has the configuration the app received as its label (fixtures only if their file is in the bundle) and the app's time zone as its value; see `LaunchConfigurationTests`.
- `debug.storedLibrary` (any screen: `screen.storedLibrary`) lists the stored books by title, one per line as `title · author · language · file name` (`no author`, `no file` when missing); see `DataModelTests`. Its value lists the files in the app's books folder, sorted, one per line (`BookActionsTests/testRemoveAsksThenDeletesBookAndFile`).
- `debug.storedHighlights` (any screen: `screen.storedHighlights`) has the number of stored highlights as its label, including any left without a book (`SelectBooksTests/testSelectedBooksAreRemovedWithTheirHighlights`).
- `debug.readingReminder` (any screen: `screen.readingReminder`) has the pending local notifications as its label, one per line as `identifier · title · body · HH:mm · repeats` (`none` when there are none), and the notification permission as its value (`notDetermined`, `authorized`, `denied`), read at launch and after each change of the reminder toggle or time, once the schedule is updated; see `ReminderTests`.
- `debug.colorScheme` (any screen: `screen.colorScheme`) has the colour scheme the app renders in as its label, `light` or `dark`, after the Theme setting and the system appearance; see `SettingsTests/testThemeOverridesSystemAppearance`.
- Notification permission is not reset by `resetsState` and cannot be changed in the simulator's Settings app: a simulator asks once, then keeps the answer until the app is uninstalled (`xcrun simctl uninstall <udid> com.ione.scholia`). Turn the reminder on with `SettingsScreen.turnOnReminder()`, which checks the system prompt's title and allows it when it comes; never deny it in a test, use `notificationPermission` instead.
- Translation mock (`App/Sources/Translation/MockTranslationProvider.swift`): every word gets the same `MockTranslationProvider.translation` (translation "vermin"), target languages are `TargetLanguage.identifiers`, no language packs. `debug.translationRequests` (any screen: `reader.translationRequests`) lists the requests that reached the mock, one per line as `word · offset in sentence (UTF-16) · source → target`; cached repeats do not appear; a `.held` request appears as soon as it is made; see `TranslationTests`, `WordBubbleTests`.
- Word tap bubble (`WordBubbleTests`): `reader.bubble` (container) with `reader.bubble.word`, `.ipa`, `.translation`, `.grammar`, `.loading` (label `Translating <word>`) and `.failure`. Tap a word with `reader.tapWord(onLine:x:)` (German fixture, first paragraph). The word tint is painted in the web view after the bubble appears: wait for `debug.paintedWordTints` (`reader.paintedWordTints`, the number of painted tint boxes) before sampling pixels.

| Fixture | Content |
|---|---|
| `.german` | "Die Verwandlung", Franz Kafka, `de`, cover, nav with Erster/Zweiter/Dritter Teil, ~2,400 words each; Zweiter Teil opens with a verse in `<br/>` lines and `<div>` paragraphs |
| `.frenchNoCover` | "Un matin en ville", Scholia, `fr`, no cover, Premier/Deuxième chapitre |

| `.drm` | "Encrypted", `META-INF/encryption.xml` (aes128-cbc), chapter bytes scrambled |

## Screen objects

```swift
struct LibraryScreen: Screen {
    let app: XCUIApplication

    var root: XCUIElement { app.searchFields["library.searchField"] }

    func book(_ title: String) -> XCUIElement { app.buttons["library.book.\(title)"] }

    func open(_ title: String) -> ReaderScreen {
        book(title).waitUntilExists().tap()
        return ReaderScreen(app: app).waitUntilShown()
    }
}
```

- `root` is the one element that proves the screen is shown.
- Actions that navigate return the next screen after `waitUntilShown()`.
- Screen objects hold queries and actions; assertions stay in tests. No pixel, colour or frame helpers.
- Unsure of the element type? `app.descendants(matching: .any)["id"]`.

## Flow tests

The worked example is `UITests/SettingsTests.swift`:

```swift
func testOpensFromHomeAndGoesBack() {
    let home = HomeScreen(app: launch(withoutBooks)).waitUntilShown()

    let settings = home.openSettings()
    XCTAssertEqual(settings.backButton.label, "Back to Home")
    settings.goBack()

    home.settingsButton.waitUntil(\.isHittable, equals: true)
}
```

- Name: `test<WhatTheUserGets>`: `testOpensFromHomeAndGoesBack`, `testEveryValuePersistsAcrossRelaunch`, `testThemeOverridesSystemAppearance`.
- Arrange (launch configuration, navigate), act (one user action or a short sequence), assert the end state the user cares about. Every test asserts an outcome, not only that a screen appeared.
- Outcomes are read through identifiers: `exists`, `waitUntilGone()`, `isSelected`, `isEnabled`, `isOn`, a row's `.label` or `.value` after the action changed it, `debug.*` diagnostics.
- The screen's look belongs to its snapshot tests, not to a flow (see Anti-patterns).

## Snapshot tests

The worked example is `UITests/SettingsTests.swift`, references in `UITests/__Snapshots__/SettingsTests/`:

```swift
func testSettingsSnapshotLight() {
    assertSnapshot(of: openSettingsWithReminder(appearance: .light), named: "Settings")
}

func testSettingsSnapshotDark() {
    assertSnapshot(of: openSettingsWithReminder(appearance: .dark), named: "Settings")
}

private func openSettingsWithReminder(appearance: XCUIDevice.Appearance) -> SettingsScreen {
    let settings = HomeScreen(app: launch(withoutBooks, appearance: appearance)).waitUntilShown().openSettings()
    settings.turnOnReminder()
    return settings
}
```

- `named:` is the design screen's file name without `.dc.html`, light variant: `Settings`, `Library-A`, `Home-Empty`, `iPad-Settings`. The helper adds the appearance: `Settings.light.png`, `Settings.dark.png`. The dark reference pairs with `<Name>-Dark.dc.html` where that exists (`Library-A.dark.png` ↔ `Library-Dark`), else with the light screen and the dark tokens. A state with no design screen gets `<Screen>-<State>` (`Settings-ReminderOff`).
- Test names: `test<Name>Snapshot<Light|Dark>`, dashes dropped: `testLibraryASnapshotLight`, `testHomeEmptySnapshotDark`.
- Drive the app to the state the design screen shows (fixtures, `now`, taps through screen objects, same data as the design where the fixtures allow), then `assertSnapshot` as the last line. Exactly one `assertSnapshot` per test, no other assertions; the screen object waits are enough to reach the state.
- One test per appearance, each launching with `launch(_:appearance:)`. Never loop over appearances in one test: the first failure stops the test and hides the other.
- Every design screen a feature builds gets a light and a dark snapshot test in that screen's own test class. States without a design screen (empty, error, long titles) get one when the look matters.
- Keep the state deterministic: `resetsState: true`, fixtures instead of imported files, `now` when dates, times, progress or the goal ring show, the translation mock.
- Do not snapshot: a focused text field (the caret blinks, the keyboard is system UI and depends on the host's hardware-keyboard setting), system UI (alerts, the notification prompt, Files picker, share sheet, context menus), anything mid-animation or loading. For those, a flow checks that they appear.

What `assertSnapshot(of:named:)` does (`UITests/Support/Snapshot.swift`):

1. Waits for the screen's `root`.
2. Captures `app.screenshot()` until two consecutive captures are identical (up to 10 s), so late layout, image decoding and fades are finished; fails if the screen keeps changing.
3. Crops the system bars: the status bar (its frame comes from SpringBoard) and the home-indicator strip (the bottom safe-area inset). The clock, battery and network change, and the same simulator drew the home indicator in one run and not in another (after a reboot it was missing, after a full suite present), so neither bar may enter a reference.
4. Compares with the reference at `precision: 1, perceptualPrecision: 0.98`: every pixel must be within ΔE 2 of the reference, the difference the eye cannot see; one misplaced line fails.
5. Records only when `SNAPSHOT_TESTING_RECORD` is set in the test runner (see below); otherwise a missing reference fails. On failure the xcresult gets `reference`, `failure` and `difference` PNGs and the message prints both file paths.

References are valid only for the simulator `scripts/sim create` prepares, with Xcode 26.4.1. An iPhone reference is 1206×2358 px: 402×786 pt at 3x, from 54 pt below the top of the screen to 34 pt above its bottom. A different device fails with a size mismatch; a different OS or Xcode fails with rendering noise. Re-record everything only when the project moves to a new Xcode or runtime, in its own commit.

## Record and review references

```sh
make snapshots DESTINATION='platform=iOS Simulator,id=<udid>' ONLY=ScholiaUITests/SettingsTests
make test DESTINATION='platform=iOS Simulator,id=<udid>' ONLY=ScholiaUITests/SettingsTests
```

- `make snapshots` runs the tests with `SNAPSHOT_TESTING_RECORD=failed` (xcodebuild passes `TEST_RUNNER_…` variables to the test runner without the prefix). Missing references and references that no longer match are written into `UITests/__Snapshots__/`, and those tests fail with "Automatically recorded snapshot" or "A new snapshot was automatically recorded" — expected. Matching references are left untouched, so unchanged screens never churn.
- Then run `make test` on the same tests: it must pass.
- Review every new or changed PNG before committing: `git status --short UITests/__Snapshots__`, open each file with Read. It must show the intended state and appearance, complete (no spinner, no half-loaded cover, no alert, no keyboard), and match the design (skill `design-compare`). For a changed one, compare it with the old version (`git show HEAD:<path> > /tmp/old.png`) and make sure every difference is intended.
- Commit the PNGs with the code change that caused them. A failing snapshot is never fixed by re-recording without explaining the difference.
- Re-record every reference (new Xcode or runtime only): `TEST_RUNNER_SNAPSHOT_TESTING_RECORD=all make test DESTINATION=…`.
- `make test` and CI never record: without the variable the mode is `never`, so a missing reference fails and a CI retry cannot pass on a freshly written file.
- A failed comparison: export the attachments (see Read failures) and open `failure_*.png` and `difference_*.png`; the failed image is also written to the runner's `tmp/<TestClass>/` (path in the message).

## Waiting, never sleeping

- `waitUntilExists()` — appeared; returns the element, so `.waitUntilExists().tap()`.
- `waitUntilGone()` — sheet dismissed, skeleton gone.
- `waitUntil(\.label, equals: "…")` — any `Equatable` key path: `\.isHittable`, `\.isSelected`, `\.isEnabled`.

They fail at the caller's line after 10 s. No `sleep`, `Thread.sleep` or fixed-delay expectations.

## Run

One simulator per worktree; never share it with another agent.

```sh
scripts/sim create Scholia-<issue>
make test DESTINATION='platform=iOS Simulator,id=<udid>'
make test DESTINATION='platform=iOS Simulator,id=<udid>' ONLY=ScholiaUITests/SmokeTests
make test DESTINATION='platform=iOS Simulator,id=<udid>' ONLY=ScholiaUITests/SmokeTests/testAppLaunches
scripts/sim delete Scholia-<issue>
```

`scripts/sim create` takes a simulator from the shared pool (queues if all are busy), boots it, pins language, region, text size and appearance, and prints the udid; `scripts/sim delete` gives it back — do that right after the run, never hold one while writing code. iPad: `scripts/sim create Scholia-<issue>-iPad --ipad`. If the runner fails to launch with "Busy" / "Application failed preflight checks", the simulator was not fully booted: run `scripts/sim create` again and rerun.

Tests that switch the appearance (`launch(_:appearance:)`, every dark snapshot) need a simulator prepared by `scripts/sim create`, which switches it once with `simctl` after booting. If a dark snapshot comes out light, reboot that simulator (`xcrun simctl shutdown <udid>`, then `scripts/sim create` again).

## Read failures

Every run writes `build/Results-<timestamp>.xcresult`; the path is printed first.

```sh
xcrun xcresulttool get test-results summary --path <bundle>
xcrun xcresulttool get test-results test-details --path <bundle> --test-id 'SmokeTests/testAppLaunches()'
xcrun xcresulttool export attachments --path <bundle> --output-path /tmp/att --test-id 'SmokeTests/testAppLaunches()'
```

- `summary` → `testFailures[].failureText`; `test-details` → call stack down to the test.
- A failed test carries `App UI hierarchy … .txt` (every element with identifier, label, frame — read it first), a UI snapshot and an `.mp4` screen recording; a failed snapshot also `reference_…png`, `failure_…png`, `difference_…png`. `manifest.json` maps files to names. `--only-failures` exports nothing here; use `--test-id`.
- Whatever is on the simulator now: `xcrun simctl bootstatus <udid> -b`, then `xcrun simctl io <udid> screenshot /tmp/shot.png`.

## Flakiness rules

- Every test launches its own app; no state or order shared between tests.
- Wait for the element that proves a transition finished, then act. Tap only after `waitUntilExists()`; during animations wait for `\.isHittable`.
- Assert end states, not animation frames or timings.
- Identifiers only: no queries by visible text, index or coordinates, except gestures on an area (e.g. tapping an empty part of the page) — take coordinates relative to a screen element.
- Tap a text field before `typeText`.
- A test that passes on retry has a missing wait: fix the wait, never add retries or longer timeouts.

## Anti-patterns

- Layout through values: `XCTAssertEqual(cover.frame.size, CGSize(width: 160, height: 240))`, comparing `frame.minX`/`maxY` of elements, row heights, gutters. Use a snapshot.
- Colour through pixels: sampling `XCUIScreenshot` (`ScreenPixels`, `color(at:)`, `RGBColor`, token colour lookups) to check a background, text or highlight colour. Use a snapshot; for "the app is dark now" use `debug.colorScheme`.
- Content through labels: asserting every row's label to prove a screen "shows the defaults" or a formatted text. Use a snapshot; assert a label only when it is the outcome of the action under test or a VoiceOver label.
- `attachScreenshot` for design review: replaced by committed references. Existing calls go when their screen is migrated.
- Snapshots in flow tests, several `assertSnapshot` calls in one test, a loop over appearances, a snapshot without its light or dark twin.
- Snapshots of system UI, a focused field, the keyboard, a loading or animating state, real dates or times.
- Recording on another device, OS or Xcode, recording in CI, re-recording a failure without looking at the difference, committing PNGs nobody opened.
- `sleep`, fixed delays, polling loops in tests, retries or longer timeouts to make a test pass.
